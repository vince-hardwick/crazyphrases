# Font Awesome Configuration

## Integration

- **Method:** Hosted SVG+JS Kit
- **Kit ID:** `613901cfcc`
- **Kit Script:** `https://kit.fontawesome.com/613901cfcc.js`
- **Version Policy:** Pin the Kit to the current Font Awesome 7 version during
  implementation; do not leave it on the default `Latest` auto-update setting.
- **License:** Owner-managed Font Awesome Kit

## Defaults

- **Family:** Classic
- **Style:** Solid for all Built-in Avatars when available in the pinned Kit;
  Classic Regular is the per-icon fallback only when a requested icon is not
  available in Solid.
- **Avatar Scope:** Built-in Avatar visuals for the Uploaded Avatar slice

## Markup Pattern

Use Font Awesome Kit-compatible inline icon markup, for example:

```html
<i class="fa-solid fa-star" aria-hidden="true"></i>
```

The icon element may be decorative, but the surrounding Avatar preview, option,
or control must expose the selected Avatar label to assistive technology.

## Conventions

- Keep Crazy Phrases Avatar keys stable as product/storage keys, even when they
  intentionally match Font Awesome icon names.
- Treat Font Awesome icon family/style/name classes as rendering metadata.
- Do not create project-local classes beginning with `fa-`.
- Do not commit Font Awesome account tokens, API tokens, or package manager
  tokens.
- Prefer a subsetted Kit containing only the Built-in Avatar icons/styles needed
  by the slice.
- Verify local/dev/test rendering before promoting changes that depend on the
  hosted Kit.
